# Comprehensive Codebase Sync Audit Report (Role-Based)

This document outlines structural data synchronization discrepancies identified during a deep-dive audit of the `secure-easy` codebase. These discrepancies cause state fragmentation across different operational portals (Sales vs Installer vs Delivery vs Finance).

## 1. CRM & Sales vs. Field Operations (Salesperson ↔ Installer)

### Issue: "Leads" vs "Jobs" Disconnect
- **How it works:** When a booking is paid online (via Razorpay webhook), the system correctly marks the Quote and Lead as `BOOKED`/`PAID`, and it **automatically generates a new document in the `jobs` collection** (assigned `PENDING_DISPATCH` or `BACKORDERED`). Admin dispatchers use `/api/admin/dispatch/jobs` to assign these jobs to an `installer_id`.
- **The Disconnect:** The **Installer Dashboard** (`/installer/jobs/page.tsx` and `/installer/dashboard/page.tsx`) completely ignores the `jobs` collection. Instead, it queries the `leads` collection for `assigned_to_installer_id`. 
- **Impact:** Jobs dispatched by the admin via the `jobs` collection will **never appear** on the installer's portal. The installer only sees leads manually assigned to them during the pre-sales process.
- **Recommended Fix:** 
  1. Migrate the Installer Dashboard to query the `jobs` collection where `installer_id == session.installerId`.
  2. Map `Lead` data (address, contact) directly into the `Job` model during dispatch, or use a joint query.

## 2. Field Operations vs Logistics (Installer ↔ Deliveryman)

### Issue: "Jobs" vs "Quotes" Disconnect
- **How it works:** Delivery staff use the `/delivery/route` portal to plan their daily deliveries.
- **The Disconnect:** The Delivery route API (`/api/delivery/route/route.ts`) queries the `quotes` collection looking for `delivery_status == 'DISPATCHED'`. It completely bypasses the `jobs` collection and the `inventory` engine.
- **Impact:** The system has bifurcated state. The Razorpay webhook creates a `job` (which handles inventory deduction), but the Delivery team drives their operations from the `quotes` collection. If an admin modifies the job status, the delivery guy never sees it.
- **Recommended Fix:** The Delivery Route planner should query the `jobs` collection for jobs with `status == 'PENDING_DISPATCH'` or `status == 'EN_ROUTE'`, standardizing fulfillment around the `jobs` entity.

## 3. Finance & Accounting (Admin/CA ↔ Webhooks/Manual)

### Issue: Invoice Schema Mismatch (CamelCase vs Snake_Case)
- **How it works:** When a payment occurs via the Razorpay webhook, it automatically creates a document in the `invoices` collection with `snake_case` keys: `total_amount`, `amount_paid`, `amount_due`, `created_at`.
- **The Disconnect:** The Finance Invoice Dashboard (`/api/finance/invoices/route.ts`) explicitly maps data expecting `camelCase` keys: `grandTotal`, `amountPaid`, `amountDue`, `issueDate`. 
- **Impact:** All real invoices generated by the production payment gateway appear in the accountant's dashboard with **$0 totals, wrong dates, or blank values**. The finance module is forced to "fallback" to parsing the raw `quotes` collection, which is unreliable.
- **Recommended Fix:** Standardize the `invoices` schema to `snake_case` across both the webhook generator and the `/api/finance/invoices/route.ts` parser.

### Issue: Manual Payments Skip Invoices & Ledgers
- **How it works:** Admins can manually record a payment via `/api/admin/quotes/manual-payment/route.ts`.
- **The Disconnect:** This route updates the `quotes` collection and adds a `transactions` record, but it **does not**:
  1. Update the parent `leads` collection.
  2. Create an `invoices` document if it doesn't exist.
  3. Deduct inventory via `InventoryEngine` or create a `job`.
- **Impact:** Customers paying cash or via offline RTGS will never get an invoice, their inventory won't be reserved, and installers won't be dispatched automatically.

## 4. Summary & Action Plan

To establish true role-wise synchronization, the data model needs strict boundaries:
1. **Sales (Promoter, Salesperson):** Owns `interest_leads`, `leads`, `quotes`. Once a quote is accepted and booked, the workflow leaves their domain.
2. **Operations (Admin, Installer, Delivery):** Owns `jobs`. A `job` is the single source of truth for fulfillment. Delivery routes and Installer tasks must both query `jobs`.
3. **Finance (Accountant, CA):** Owns `invoices`, `transactions`, `finance_ledger`. All payment pathways (Razorpay, Offline, Manual) must pipe through a unified `PaymentService` that creates identical ledger and invoice documents.
